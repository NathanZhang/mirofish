# MiroFish 初始输入要求与模板

适用于本仓库的 MiroFish 本地版，整理日期：2026 年 10 月 28 日。

当前版本在操作上最低只需“一份材料文件＋一段模拟提示词”：首页支持上传 TXT、MD、PDF，填写模拟提示词后即可提交。要让模拟结果有分析价值，应在材料中说明场景、参与者、已知事实、拟议变化和未知事项。

## 一、最少需要哪些信息

| 信息 | 最少需要回答的问题 |
|---|---|
| 场景与目标 | 发生什么事？希望通过模拟辅助什么决策？ |
| 参与者 | 谁参与？各方负责什么、关心什么？ |
| 已知事实 | 当前情况、已有规则、时间背景是什么？ |
| 待讨论的变化 | 准备实施什么方案？有哪些明确约束？ |
| 未知事项 | 哪些尚未决定，需要通过讨论发现问题？ |

不必预先编写知识图谱、关系三元组或完整人物画像，也不必填写年龄、性别、MBTI。系统会生成本体、图谱和角色配置；生成内容仍需人工核对。

角色可以是具体的人，也可以是“客户支持”“团队管理员”“外部协作者”等利益相关方。关键是写清职责和诉求，否则容易出现多个角色重复表达相似观点。角色人数不是系统硬性要求，应按场景选择有不同职责或利益的参与者。

## 二、材料文件模板

将下面内容复制到文本文件，替换方括号中的说明，保存为 `场景材料.txt` 后上传。也可以保存为 Markdown 文件。

```text
项目名称：[填写名称]
材料性质：[真实业务材料 / 虚构演练]
时间基准：[截至哪一天，或明确的场景时间]

一、场景与目标
当前情况：[用2—3句话说明背景]
拟议变化：[准备推出的政策、产品、活动或流程调整]
本次需要辅助的决策：[例如发现公告遗漏、识别执行阻力、完善方案]

二、参与者
角色A：[名称或身份]
职责或影响：[负责什么，或会受到什么影响]
主要诉求：[关心什么]
与其他参与者的关系：[协作、管理、服务、利益冲突等]

角色B：[按上述格式填写]
角色C：[按上述格式填写]
[按需要增加角色；人数不是系统硬性要求]

三、已知事实与明确规则
1. [已经确认的事实]
2. [当前规则与拟议规则，分别写清]
3. [时间、人数、预算、资源或权限约束]
4. [必要时注明来源及日期]

四、尚未决定或尚不清楚的事项
1. [待决问题]
2. [缺少的信息]
3. [需要验证的假设，明确标记“假设”]

五、材料边界
只有明确列出的事实和规则可以作为确定背景。
未提供的信息应标记为未知，不能自行补成已批准规则。
生成的情节、观点和建议应与材料事实区分。
```

## 三、模拟提示词模板

将下面内容复制到首页的模拟提示词输入框，替换方括号中的说明。

```text
请依据上传材料，模拟[场景/方案]实施后，各参与方的讨论与相互回应。

本次重点回答：
1. [最想发现的问题]
2. [最关心的分歧或风险]
3. [希望完善的规则或措施]

以材料中的人物、组织或业务角色为参与者。
保持不同角色的职责、利益和关注点差异。
不得预设所有人支持方案，也不得预设方案必然失败。
缺少的背景应明确标记为未知或假设。

请用中文输出：
1. 关键观察；
2. 各方支持、反对和追问的内容；
3. 主要分歧及其原因；
4. 建议补充的规则、说明或FAQ；
5. 每项主要发现对应的模拟发言依据；
6. 仍需真实用户或业务负责人验证的事项。

区分材料事实、初始配置帖、角色自主发言和分析推断。
不要把模拟中的发言比例解释为真实人群的支持率。
```

这些提示用于约束生成方向，不能替代对角色配置、实际发言和最终报告的人工检查。

## 四、已有案例与使用注意事项

首次试用可以参考已经验收过的虚构共享阅读室案例：

- [共享阅读室材料](examples/shared-reading-room-seed.txt)：作为上传文件。
- [对应模拟提示词](examples/shared-reading-room-requirement.txt)：复制到首页输入框。
- [案例与功能说明](MiroFish案例与功能说明.md)：了解完整流程、实际结果和验证依据。
- [操作手册](MiroFish操作手册.md)：查看启动、运行参数、记忆确认和报告生成步骤。

使用时注意：

1. **运行轮数应在启动参数中设置。** 提示词里写“最多3轮”不能保证程序只运行3轮。严格三轮运行应使用运行页参数 `?maxRounds=3` 或启动 API 的 `max_rounds=3`，具体步骤见操作手册。
2. **当前版本不保证角色之间的私有信息隔离。** 共用材料应以各方可见信息为主；内部评审答案或保密底稿应单独保存。提示词中写“某角色不知道”不能保证隔离。
3. **模拟输出用于发现问题和辅助评审。** 生成的观点、角色画像和情节不等于真实用户调查结果；涉及业务决策的发现仍需验证。
